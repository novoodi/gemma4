# 모이미 — 개발 기여와 검증 증빙 점검

점검일: 2026-09-13. 목적: 교수님께 작품의 정체성, 직접 구현한 범위, 검증 근거를 설명하기 위한 자료.

## 1. 작품과 개발 기여를 설명하는 문장

> 모이미는 단체 대화의 일정·취향과 과거 후기를 바탕으로 모임 장소와 활동을 추천하는 Android 앱입니다. 기존 Gemma·Gemini·EmbeddingGemma 모델을 사용하고, 저희는 대화 처리, 후기 저장·검색, 도구 호출, 추천 검증·재시도를 연결하는 응용 시스템을 구현했습니다.

“이미 있는 것을 가져온 것 아니냐”에는 다음처럼 답할 수 있습니다.

> 모델과 추론 엔진은 기존 기술을 사용한 것이 맞습니다. 프로젝트에서 구현한 것은 모델이 처리할 데이터의 구성, 과거 후기를 검색하는 과정, 도구 호출 결과를 연결하는 실행 루프, 불호 위반 검사와 재추천 정책입니다. 이 로직은 소스 코드와 기능별 테스트·변경 이력으로 보여드릴 수 있습니다. 다만 새로운 학습 알고리즘이나 AI 모델을 개발했다고 주장하지는 않습니다.

이 문서의 “직접 구현”은 저장소에 프로젝트 로직이 존재한다는 분류다. 코드가 외부 예제에서 전혀 유래하지 않았는지, 각 팀원이 어느 부분을 직접 작성했는지까지 독립적으로 입증한 것은 아니다. Git 이력은 변경 과정의 근거이며 독창성·개인별 작성 능력의 보증은 아니다.

## 5. 지금 있는 앱 로그로 볼 수 있는 것

AgentOrchestrator는 AgentEvent를 발행하고, ChatViewModel이 화면 디버그 목록으로 변환한다.

| 기록 | 활용할 수 있는 관찰 |
|---|---|
| GemmaSummaryCompleted | 요약 결과, 요약에 대한 마스킹 수·종류 |
| PromptGenerated | 실제 구성 프롬프트, 추천 시도 번호 |
| ToolCalled | 도구 이름·인자·결과, 이벤트를 집계하면 호출 수 |
| GuardrailEvaluated | 시도별 검증 결과와 UNKNOWN 수 |
| ReflectionEvaluated | 시도별 감지한 불호 위반 수·내용 |
| OrchestrationFinished | 성공/실패, 시도 수 |
| EmbeddingGemmaRetriever의 Logcat | 후보 수, top-k 수, 최고 코사인 |

현재 화면 로그는 MutableStateFlow 목록이며 추천 시작 시 초기화된다. 살펴본 경로에는 이를 실험별 파일로 영속 보관하거나 CSV/JSON으로 내보내는 기능이 없다. 단계별 소요시간·토큰·API 비용을 집계하는 기능도 확인하지 못했다. Room에 저장되는 추천 결과와 실행 로그는 별개의 데이터다.

따라서 “로그를 볼 수 있다”와 “과거 실험 원본이 보관되어 있다”를 구분해야 한다. 향후에는 합성 대화로 실험하고 runId, 단계 시각, 모델/앱 버전, 시도 수, 검증 결과 같은 수치를 별도 저장하면 된다. 원문이나 개인정보를 외부에 보내는 방식으로 수집해서는 안 된다.

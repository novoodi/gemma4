> 표지는 중간 보고서 원본 양식을 그대로 사용한다. 작성 방침: 원본의 절 구성(3 기능 → 5 인터페이스 → 6 성능 → 8 보안 → 7 데이터 → 9 품질)과 표 항목(요구사항 번호·유형·이름·개요·내용·입출력·중요도·위험도·품질속성·평가 방법·관련·출처)은 그대로 두고, **현재 코드(2026-09)와 어긋나는 항목은 교정하고 빠진 항목은 추가**한다. 【변경】= 원본과 내용이 다름, 【추가】= 원본에 없던 항목, 【삭제】= 코드에 없는 기능이라 제거.

| 요구사항 내용 | 1.1 시스템은 Android Credential Manager로 Google 계정 선택과 ID 토큰 발급을 요청하여야 한다.<br>1.2 시스템은 ID 토큰으로 Firebase Authentication 인증을 수행하고 UID로 사용자를 식별하여야 한다.<br>1.3 시스템은 UID 기반으로 채팅 발신자를 구분하여야 한다.<br>1.4 시스템은 로그인 완료 후 온보딩 완료 여부에 따라 메인 화면 또는 온보딩으로 이동하고, 온디바이스 모델이 없으면 모델 다운로드 화면을 먼저 안내하여야 한다.<br>1.5 시스템은 로그인 실패·취소 시 오류 메시지를 표시하고 로그인 화면을 유지하여야 한다.<br>1.6 시스템은 로그인 확정 시 기기의 FCM 토큰을 발급해 `users/{uid}.fcmTokens`에 저장하여야 한다. |

## 7. 데이터 요구사항 (Data Requirements)

### 7.1 개요 【변경】

본 시스템은 두 가지 저장소(Cloud Firestore, Room)와 여섯 종류의 외부 인터페이스를 사용한다. 채팅 원문은 Firestore에 저장되어 참여자 간 동기화되지만 AI 처리는 온디바이스에서만 이루어지며, 정제된 성향·후기·추천 데이터만 기기의 Room DB에 저장한다. 캘린더 일정은 현재 앱 메모리에만 유지된다.

| 저장소 | 유형 | 저장 대상 |
|---|---|---|
| Cloud Firestore | 클라우드 | 사용자(온보딩 완료·FCM 토큰), 방별 읽은 시각, 모임방, 메시지, 초대코드 |
| Room (moim_database) | 로컬(온디바이스) | 성향 프로필(user_status), 후기+임베딩(feedback), 추천 결과(meeting_summary), 추천받은 방(recommended_room) |
| 앱 메모리 | 로컬(휘발) | 캘린더 일정(CalendarEvent) |
| 외부 파일 저장소 | 로컬 | 모델 파일 3종(Gemma 4 E2B, EmbeddingGemma, 토크나이저) |

| 외부 인터페이스 | 송신 | 수신 |
|---|---|---|
| Google 로그인 / Firebase Auth | Google ID 토큰 | UID, 표시 이름, 이메일 |
| Cloud Functions 프록시 | callable 데이터(JSON) + Firebase Auth 토큰 | 업스트림 JSON 그대로 |
| Gemini (프록시 경유) | 마스킹 요약, 성향 프로필, 마스킹 후기, 도구 명세·결과 | 툴 호출 또는 추천 JSON |
| 기상청 중기예보 (프록시 경유) | 구역코드, 발표시각 | 날씨 상태·강수확률·최저/최고 기온 |
| 카카오 로컬 (프록시 경유) | 검색어, 건수 | 장소 문서(상호·주소·전화·지도 링크), 총 건수 |
| FCM | 토큰 목록, 알림 페이로드(Function에서) | 푸시 알림 |

### 7.6 데이터 제약 조건 【변경】

**보안 및 개인정보**
1. 채팅 원문은 Gemma 4 온디바이스 추론에만 사용하며 외부 서버로 전송하지 않는다.
2. Gemini에는 PiiScrubber를 통과한 요약문·후기와 비식별 성향 프로필만 전송한다.
3. Room에는 정제된 프로필·후기·벡터·추천 결과만 저장하고 채팅 원문은 저장하지 않는다.
4. 외부 API 키는 앱에 두지 않으며 프록시는 로그인 사용자만 호출할 수 있다.
5. (구현 예정) Gemini 호출은 사용자 명시적 동의 후에만 수행한다.

**데이터 정합성**
6. 방의 마지막 멤버가 나갈 때 messages·inviteCodes·rooms 문서를 함께 삭제한다.
7. 방 나가기 시 해당 방의 user_status·meeting_summary를 삭제한다.
8. user_status는 직전 상태와 합집합 병합하며 리스트당 최대 25건(오래된 항목부터 폐기)을 유지한다.
9. 임베딩이 없는 feedback은 앱 시작·모델 설치 시 재인덱싱한다.

**처리 조건**
10. 기상청 조회는 오늘부터 3일 이후 10일 이내 날짜에만 수행하고, 미정·범위 밖은 안내 문구로 대체한다.
11. 추천 장소의 검증 상태는 VERIFIED / NOT_FOUND / UNVERIFIED 3-상태로 저장·표시한다.
12. 도구 실패는 해당 항목만 비우고 분석을 계속한다. Gemini 3회 실패는 전체 실패다.

**응답 성능**
13. 목록 조회·생성 3초, 메시지 반영 1초, 푸시 3초 이내.
14. 프록시 업스트림 60초, 클라이언트 Gemini 120초·도구 30초 타임아웃.
